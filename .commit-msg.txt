test: cover the shared delete core and drop a dead helper

The refactor that extracted delete-core gave three entry points (tool,
slash command, CLI) one implementation, but nothing tested that core
directly: every existing test went through a caller. Adds 13 tests pinning
what the core itself guarantees - filesystem roots refused, the safe
zone's own directory refused, missing paths reported rather than created,
preview changing nothing, approval asked once on a dangerous path and
honoured when rejected, and thresholds reported alongside the reason.

Also runs a mutation pass over those tests: seven deliberate breakages
(remove the root check, the safe-zone check, the existence check, the
approval gate, the rejection handling, either threshold) each turned the
suite red. The tests have teeth rather than passing by construction.

Two real findings while checking:

- store.ts exported safeZoneBytesOnDisk, which nothing called and which
  duplicated safeZoneBytes in prune.ts. Removed.
- the fake context used while probing had its home under the OS temp
  directory, so the temp-exemption rule classified it free and the confirm
  branch was never reached. The test fixtures set tmpdir explicitly for
  the same reason; that is now also asserted by a test.
