fix: close three silent interception gaps found by adversarial probing

A guard that misses a form fails silently: the user believes deletion is
protected while the channel sits wide open. Three classes were missing:

- commands that execute a quoted string (cmd /c, sh -c, powershell -Command,
  Invoke-Expression): tokenizing kept the quoted segment as one token, so the
  delete verb inside never matched
- deletes with no delete verb (find -delete, rsync --delete, .Delete(),
  .unlink(), .rmdir(), perl unlink)
- quoted targets containing spaces were split, so classification ran on a
  truncated path

Also stops treating prose as deletion: comments are stripped, and read-only
commands (echo, grep, console.log) are exempted, so writing a document that
mentions rm -rf no longer trips the guard.

Adds tests/interception-safety.test.ts pinning both directions, plus three
probe scripts and a docs-vs-code consistency check.
